## macOS Electron 打包与验收

在完成全仓构建后使用 `pnpm --filter @orchestrator/desktop make`。仓库根的 `pnpm desktop:make` 会先全仓构建，再调用这个打包命令。打包目标为 Electron 38.8.6、Darwin arm64，server 和 web 独立存放在 `.app/Contents/Resources`，主进程与 preload 存放于 `app.asar`。

打包过程中的问题与处理如下。

1. 首次打包在 `prepare-resources.mjs` 删除暂存目录后停止，报 `.bin/acorn` 的 `ENOENT`。pnpm 在 macOS 创建相对符号链接，Node 默认复制将它改写为指向暂存树的路径。复制时保留链接内容后，资源检查通过。暂存的 server 依赖与代码约 822.1 MiB，web 约 0.6 MiB。
2. 第一份 ZIP 可解包为 Mach-O arm64，但严格签名校验提示资源未被封签。启用 Electron Packager 的临时签名后，进一步发现 Packager 会将部分依赖链接展开成构建工作区的绝对路径，签名验证报告 `invalid destination for symbolic link in bundle`。复制资源后恢复包内相对链接，再进行 ad hoc 签名。严格签名校验通过后，直接启动还复现了 dyld 的 Team ID 不匹配。本机 ad hoc 包缺少 Team ID，因此这条本机打包路径使用非 Hardened Runtime 配置。
3. 默认的 Packager 下载器会为已有的 Electron 缓存重新取得远端校验文件，曾在读取该文件时等待较久。配置 Packager 使用安装包自带的官方发布校验值验证本地缓存，沿用 Electron 安装脚本支持的远端校验开关。
4. 桌面窗口启动改为确认 `running.json` 中的 PID 属于自身刚启动的服务子进程，并且 URL 指向其回环端口，避免复用其他进程留下的地址。macOS 关闭最后一个窗口时应用保持运行，activate 时从现有服务重新打开窗口。

从最终 ZIP 用 `/usr/bin/ditto -x -k` 解压到临时目录。独立检查了可执行文件架构、`.bin/acorn` 在包内的相对链接及目标文件，并通过 `codesign --verify --deep --strict`。从解压目录运行整个应用，测试进程 PATH 只包含 macOS 系统目录。

- 预先放入一份引用其他存活 PID 的旧 `running.json`。确认窗口加载新的本机子进程 URL，`app.isPackaged=true`，Electron 为 38.8.6，自带 Node.js 为 22.22.0。工作台渲染成功，健康检查返回 `ok=true`。
- 通过渲染进程调用 preload 的目录选择方法，拦截系统对话框并返回临时目录。IPC 返回 `picked=true` 和该路径。对话框本身的手动选取操作未覆盖。
- 从打包版表单新建运行 `run-mwklweoy-84186c61`，经 API 批准一次并完成 5 个节点。关闭最后一个窗口后，触发 macOS activate 重新打开同一后端的窗口；退出应用后确认后端 PID 已结束。
- 最终 ZIP 为 `apps/desktop/out/WorkflowOrchestrator-mac-arm64.zip`，427 MiB（447,598,177 字节）。SHA-256 为 `6dd6c62aab4933375bb864643515281b5c1d5e50227b5f1eaafa0937a331f109`。未压缩的应用位于 `apps/desktop/out/WorkflowOrchestrator-darwin-arm64/WorkflowOrchestrator.app`。

验收覆盖这台 Apple Silicon Mac 的本机 ad hoc 包。Intel、Windows、Developer ID 签名与 Apple 公证未在本轮验证。其他 Mac 的分发验收还需验证正式签名、公证和安装流程。

## 代码审查

| 级别 | 位置 | 发现和影响 | 处理 |
| --- | --- | --- | --- |
| P2 | `apps/desktop/src/main.ts`，`waitForServer` | 旧逻辑凭运行文件中的 PID 是否存活决定加载 URL。相同数据目录已有 Web 进程时，桌面壳可能先打开另一个服务，随后自己的子进程因锁冲突退出。 | 已改为匹配本次子进程 PID，并校验地址等于该端口的 IPv4 回环 URL。子进程提前结束时启动流程提前报错。 |
| P2 | `apps/desktop/scripts/prepare-resources.mjs`，资源复制 | macOS 上 pnpm 生产树含相对符号链接。Node 默认复制会重写链接目标，删除暂存树后资源自检在 `.bin/acorn` 上收到 `ENOENT`。 | 已使用 `verbatimSymlinks: true`，保留包内相对链接。 |
| P2 | `apps/desktop/scripts/prepare-resources.mjs`，`pnpm deploy --prod --legacy` | hoisted + legacy 部署时 pnpm 明确提示跳过锁文件，重新解析出生产树，并给出 Claude SDK/Zod 和 OpenTelemetry 的 peer 警告。因此源码测试中的依赖版本和发布包可能不同。 | 保留本次已测试的打包模式。后续可迁移到基于 workspace lock 的 deploy，并验证 workspace 构建产物同步。 |
| P2 | `packages/server/src/app.ts`，`POST /api/runs` | 目标目录检查早于显式 DAG 的解析和校验。检查会创建目录、初始化 Git 和准备 HEAD，后续返回 `invalid_dag` 或 `dag_rejected` 时这些磁盘副作用已经发生。 | 建议先完成可独立执行的请求校验，再准备工作区。为无效 DAG 加「不触碰目标目录」的回归用例。 |
| P2 | `packages/server/src/app.ts`，`resolveActor` 与审批路由 | 审批和转交使用请求头或请求体中自报的操作者。归属检查因此只约束应用内的协作流程。若将服务开放给多人，这个字段无法提供可信的审计身份。 | 保持回环使用。若后续加入多人部署，使用经认证的服务端身份参与审批授权与审计。 |
| P3 | `packages/server/src/app.ts`，`setNotFoundHandler` | 静态模式对未知非 API URL 一律回送 `index.html`。资源丢失时浏览器可能收到 HTTP 200 和 HTML，增加定位版本错配与部署故障的时间。 | 建议仅对页面导航回退 SPA，缺失的静态资源返回 404。 |
| P3 | `packages/server/src/app.ts`，`pickDirectory` | macOS 浏览器的原生目录选择分支返回 `unsupported`。Web 用户需手填路径。Electron 单独经 preload/IPC 提供目录对话框。 | 保留现有平台行为，列入测试范围。 |
| P3 | `tests/package.json`、`packages/web/package.json` | 两处配置 `--passWithNoTests`。空套件仍返回成功，CI 配置又只在 Ubuntu 跑构建、类型和测试，现有 CI 不覆盖 macOS 打包或浏览器交互。 | 将本报告的浏览器与桌面冒烟用例纳入后续 CI，可单独设置 macOS job。 |
